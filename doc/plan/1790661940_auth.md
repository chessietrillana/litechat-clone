# Plan: auth

Based on: `doc/study/1790660517_litechat-core.md` (build order item 2, NOTE on Q27).

Goal: users can sign up with a username and password, log in, and log out.
There is a shared base template and a home page that only logged-in users can see.

Branch: `feat/auth`, made from `main`.

## Decisions made in this plan

- **Sign-up:** username + password + password confirmation, using Django's `UserCreationForm`. No email, no email verification (NOTE Q27). Django's default password rules apply (min length 8, not too common, not all numbers, not too close to the username).
- **After sign-up:** the new user is logged in at once and sent to the home page.
- **Login and logout:** Django's built-in `LoginView` and `LogoutView`. No custom auth code.
- **Logout is a POST.** Django 5 does not allow logout by GET. The nav bar has a small "Log out" form button, not a link. This will be recorded as a footgun.
- **Logged-in users** who open the login or sign-up page are sent to the home page.
- **URLs:** `/` (home), `/accounts/signup/`, `/accounts/login/`, `/accounts/logout/`. URL names: `home`, `signup`, `login`, `logout`.
- **Not in this plan:** password change, password reset (needs email), profile page. An admin can reset a password in the Django admin.
- **Where code lives:**
  - New app `accounts` for sign-up, login, and logout.
  - The home view is in `config/views.py` for now. The chat plan will replace the home page later.
  - Shared templates (`base.html`, `home.html`) go in a project `templates/` folder. `settings.TEMPLATES["DIRS"]` points there.
  - App templates go in `accounts/templates/`.
- **Styling:** one small plain CSS file, `static/css/site.css`, linked from `base.html`. No framework. Just enough to make forms and errors readable.
- **User model:** Django's built-in `User`. We do not add a custom user model. (Changing to a custom user model later is hard. We don't expect to need one, because billing data will live in its own models.)

## Steps

- [ ] **1. Base template and login-required home page**
  - Files:
    - `config/settings.py`: `TEMPLATES["DIRS"] = [BASE_DIR / "templates"]`, `STATICFILES_DIRS = [BASE_DIR / "static"]`, `LOGIN_URL = "login"`, `LOGIN_REDIRECT_URL = "home"`, `LOGOUT_REDIRECT_URL = "login"`.
    - `config/views.py` (new): `home` view with `@login_required`.
    - `config/urls.py`: `path("", home, name="home")`.
    - `templates/base.html` (new): page shell, title block, nav bar, Django messages, content block.
    - `templates/home.html` (new): "Hello, <username>." and a short note that chat is coming.
    - `static/css/site.css` (new).
    - `config/tests.py`: add tests.
  - Nav bar in this step shows only the site name. Login/logout links come in step 2.
  - Tests:
    - An anonymous user who opens `/` is redirected to `/accounts/login/?next=/`. (Checked without following the redirect, since the login page does not exist yet.)
    - A logged-in user who opens `/` gets 200 and sees their username.
    - `venv/bin/python manage.py check` passes.
  - Commit: `feat: add base template and login-required home page`

- [ ] **2. Login and logout**
  - Files:
    - `accounts/` (new app, from `venv/bin/python manage.py startapp accounts`). Add `"accounts"` to `INSTALLED_APPS`.
    - `accounts/urls.py` (new): `login` (`LoginView` with `redirect_authenticated_user=True`) and `logout` (`LogoutView`).
    - `config/urls.py`: `path("accounts/", include("accounts.urls"))`.
    - `accounts/templates/registration/login.html` (new): login form with CSRF, errors, and a link to sign up (the link is added in step 3).
    - `templates/base.html`: nav shows "Log in" for visitors, or the username and a "Log out" POST button for logged-in users.
    - `accounts/tests.py`.
  - Tests:
    - `GET /accounts/login/` returns 200 and shows the form.
    - Good username and password: logs in and redirects to `/`.
    - Bad password: stays on the page, shows an error, and the user is not logged in.
    - `?next=` is respected: log in from `/accounts/login/?next=/` and end up on `/`.
    - A logged-in user who opens the login page is redirected to `/`.
    - `POST /accounts/logout/` logs out and redirects to `/accounts/login/`.
    - `GET /accounts/logout/` returns 405 and the user stays logged in.
    - The home page nav shows the "Log out" button when logged in.
  - Commit: `feat: add login and logout`

- [ ] **3. Sign-up**
  - Files:
    - `accounts/views.py`: `SignUpView` (a `CreateView` with `UserCreationForm`). On success it logs the user in and redirects to `/`. A logged-in user is redirected to `/`.
    - `accounts/urls.py`: `path("signup/", ..., name="signup")`.
    - `accounts/templates/accounts/signup.html` (new): username, password, and confirm password, with the password rules shown and errors listed.
    - `accounts/templates/registration/login.html`: add "No account? Sign up" link.
    - `templates/base.html`: add "Sign up" to the visitor nav.
    - `accounts/tests.py`: add tests.
  - Tests:
    - `GET /accounts/signup/` returns 200 and shows username and two password fields, and no email field.
    - Valid sign-up: creates the user, logs them in, and redirects to `/`.
    - Taken username: shows an error and creates no user.
    - Passwords don't match: shows an error and creates no user.
    - Weak password (e.g. `12345678`): shows an error and creates no user.
    - A logged-in user who opens the sign-up page is redirected to `/`.
    - The new user is not staff and not a superuser.
  - Check during this step: Django 5.2's `UserCreationForm` shows only username and two password fields. If it shows anything else (such as a "usable password" choice), stop and tell the human.
  - Commit: `feat: add sign-up page`

- [ ] **4. Record the logout footgun**
  - Files: `doc/wiki/footguns/django-logout-requires-post.md` (new).
  - Content: since Django 5.0, `LogoutView` accepts only POST. A plain `<a href>` logout link returns 405. Use a small form with a CSRF token.
  - Test: none (docs only).
  - Commit: `docs: record Django logout-requires-POST footgun`

## At rendezvous (human does this)

Start the server in your own terminal: `venv/bin/python manage.py runserver`. Then:

1. Open http://127.0.0.1:8000/. You are sent to the **Log in** page, because you are not logged in.
2. Click **Sign up**. Try username `alice` with password `12345678` in both boxes. You should see a password error.
3. Now use a strong password (e.g. `correct-horse-42`) in both boxes. Click **Sign up**. You land on the home page, which says "Hello, alice." The nav shows `alice` and a **Log out** button.
4. Click **Log out**. You are back on the **Log in** page.
5. Log in as `alice` with a wrong password. You should see an error.
6. Log in as `alice` with the right password. You land on the home page.
7. While logged in, open http://127.0.0.1:8000/accounts/signup/. You are sent to the home page.
8. Open http://127.0.0.1:8000/admin/ and log in as your admin user. Click **Users**. You should see `alice`, not marked as staff.
