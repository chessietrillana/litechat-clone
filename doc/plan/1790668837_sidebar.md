# Plan: sidebar (rename and delete chats)

Based on: `doc/study/1790660517_litechat-core.md` (build order item 8; core feature 3; NOTE Q21).

Goal:

- Users can rename a chat from the sidebar.
- Users can delete a chat from the sidebar. Delete **hides** the chat (NOTE Q21):
  - it leaves the sidebar
  - its URL returns Not found
  - its charges stay in the ledger
  - the user must confirm first
- On the Usage page, a deleted chat's charges stay listed. The title shows as plain text with "(deleted)" and no link.
- Only the chat's owner can rename or delete it.

**Already done in plan 6:** listing chats in the sidebar and reopening them.

Branch: `feat/sidebar`. The plan file is committed on this branch, as asked, and not on `main`.

## What exists now

- Packages: Django 5.2.17, python-dotenv 1.2.3. Nothing new is needed.
- `ChatSession` has `user`, `llm_model`, `billing_account`, `title` (max 100 characters, default "New chat"), `created_at`, `updated_at`.
  - Auto titles are the first 6 words, at most 60 characters (`make_title`).
  - The sidebar sorts by `updated_at`, which the chat services set on every turn.
- `render_chat` in `chat/views.py` passes the sidebar list: `request.user.chat_sessions.all()`.
- `session_detail` finds the chat with `pk` and `user=request.user`. Another user's chat is already Not found (404).
- Charges already outlive their chats. `ChatMessage.charge` is protected, and a test checks that a deleted chat keeps its charge.
- The Usage page links each charge to its chat through `charge.chat_message.session`.
- The admin shows chats read-only. It can't add, change, or delete them.
- `chat.js` only handles the send forms. The pages work without JavaScript.
- `_messages.html` (Django messages) is already shown at the top of the chat column.

## Decisions made in this plan

- **Hiding is a timestamp:** a new field `ChatSession.hidden_at` (date and time, empty = visible).
  - A timestamp, not a yes/no field, so the admin can see when it was deleted.
  - The code calls it "hidden". The pages say "delete", as you asked.
  - A `visible()` queryset method. Every user-facing lookup uses it: the sidebar, the chat page, sending, rename, and delete.
  - Nothing is removed from the database. The chat, its messages, and its charges all stay.
- **Hidden chats are Not found (404) everywhere for the user:** GET and POST on the chat page, rename, and delete.
  - A POST to a hidden chat sends nothing to the proxy and charges nothing.
  - Another user's chat is also Not found, as today. Owners only; no 403 page that would show the chat exists.
- **Sending checks too.** `send_turn` refuses a hidden chat with a `ChatError` ("This chat was deleted.") before the proxy call.
  - The view already gives 404 first. This is a second guard at the service level.
  - A send that is already waiting for the proxy when the chat is deleted in another tab still saves and is charged. The tokens were used. This goes in the footgun doc.
- **Where the controls are (no JavaScript needed):**
  - Each chat in the sidebar gets a small "⋯" button, built with HTML `<details>`. It opens to two links: **Rename** and **Delete**.
  - The button's label for screen readers says "Options for <title>".
  - **Rename** opens a small page (`/chat/<id>/rename/`) in the chat layout, with the sidebar. It has a title box filled with the current title, **Save**, and **Cancel**.
  - **Delete** opens a confirm page (`/chat/<id>/delete/`), also in the chat layout. It asks "Delete "<title>"?" and says that the chat leaves your list, can't be opened again, and that its charges stay on the Usage page. It has a red **Delete** button and **Cancel**.
  - Why pages, not a JavaScript `confirm()` box: they work without JavaScript, like the rest of the app, and they are easy to test.
- **Rename rules:**
  - Spaces at the start and end are removed. A blank title is refused: "Enter a title."
  - Max 100 characters (the column's size). Longer is refused, with Django's usual "at most 100 characters" message. The box also has `maxlength="100"`.
  - Any other text is allowed, including a title another chat already has.
  - A rename does **not** move the chat to the top of the sidebar. Only `title` is saved, not `updated_at`.
  - After **Save**: back to the chat, with the new title in the sidebar and the header. A message says "Chat renamed."
  - An error shows on the rename page, with the typed text kept.
- **Delete:**
  - GET shows the confirm page. Only a POST deletes (hides). A link or a prefetch can't delete a chat.
  - After deleting: go to the new chat page (home). A message says "Deleted "<title>"."
  - Deleting a chat that is not the open one works the same way.
  - Deleting twice (for example, two tabs): the second POST is Not found. Nothing changes.
- **Usage page:** a charge from a hidden chat shows `<title> (deleted)` as plain text, with no link. The model, tokens, and cost still show. No extra database queries (the session is already loaded).
- **Admin:** stays read-only. The chat list shows a "Hidden at" column and a **Deleted by user** filter (yes / no). Admins still see hidden chats and their messages.
- **Not in this plan:** undelete, deleting for real, and deleting many chats at once. These go under "Later" in `TODO.md`.

## Review points

- **Separate pages for rename and delete**, reached from the "⋯" menu. The other choice is a rename box right inside the sidebar, with a JavaScript `confirm()` for delete. That is fewer clicks, but needs JavaScript. Recommendation: pages.
- **After delete, go home** (the new chat page), even if another chat was open. The other choice is to stay on the open chat. That is harder to get right and the gain is small. Recommendation: home.

## Browser check (for the rendezvous)

1. Log in as alice. Have at least three chats in the sidebar.
2. Click "⋯" next to a chat that is not open. See **Rename** and **Delete**.
3. Click **Rename**. The box shows the current title. Clear it and click **Save**. See "Enter a title."
4. Type "Trip ideas" and click **Save**. You are back in that chat. The sidebar and the header say "Trip ideas". The chat did not move in the list.
5. Click "⋯" → **Delete** on "Trip ideas". Read the confirm page. Click **Cancel**. Nothing changed.
6. Click "⋯" → **Delete** again, then the red **Delete** button. You are on the new chat page. It says "Deleted "Trip ideas"." It is gone from the sidebar.
7. Paste the old chat URL (for example `/chat/5/`) into the address bar. See Not found.
8. Click **Usage**. The charges from "Trip ideas" are still there, shown as "Trip ideas (deleted)" with no link. Your balance did not change.
9. In the admin, **Chat sessions**: filter **Deleted by user** = Yes. See "Trip ideas" with its hidden time. Open it and see its messages.
10. Log in as another user in a private window. Open `/chat/<alice's chat id>/rename/` and `/delete/`. See Not found.
